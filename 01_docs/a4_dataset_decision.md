## 一、双路线对比

| 维度 | 路线 A：NYC TLC FHVHV 真实子集 | 路线 B：Python 生成器（faker + 固定 seed） | 优胜 |
|---|---|---|---|
| 真实性 | 真实运营数据（Uber/Lyft 高量网约车月度记录，公开可引用） | 仿真数据；分布参数可**参照 TLC 真实分布标定**（车费区间、时段高峰），"像真的"但不真实 | A（弱优） |
| 许可 | 公开数据集，需在报告引用来源与许可说明 | 无第三方许可问题，`03_data/source/` 放生成说明即可 | B |
| **字段适配** | **致命短板**：无乘客身份（无 psg_id）、无支付方式字段、按 base 聚合无司机-车辆 1:1 绑定——五实体中 Passenger/Driver/Vehicle/Payment 四张表的关联列都要人工捏造映射，"真实性"反而在映射中丢失 | 按官方 DDL 五表**原生生成**，外键关系、UNIQUE 约束、分布（司机:乘客≈1:20、支付方式占比、高峰时段）全部可控 | **B（决定性）** |
| 导入成本 | 下载 parquet → 清洗 → 字段映射脚本，多一道易错环节且跨机版本漂移风险 | `python import_data.py` 一条命令；依赖锁 `requirements.txt` | B |
| 可复现性 | 取决于抽样脚本（抽样行不同即数字不一致） | 固定 seed，五台机器跑出**逐行一致**的数据，截图数字对得上（协作纪律第 3 条） | B |
| 规模弹性 | 月度文件体量大，抽样到 5 万行需自定规则 | Trip 行数、分布参数即改即得，便于扩到 10 万行级 | B |

## 三、样本规模与分布建议（C4 落地参数）

| 表 | 行数 | 说明 |
|---|---|---|
| Passenger | 3,000 | |
| Driver | 150 | 司机:乘客 ≈ 1:20（方案给定比例） |
| Vehicle | 150 | 与 Driver 一一绑定（N:1，vehicle_id UNIQUE） |
| Trip | **60,000** | ≥ 5 万行 M2 硬指标，留余量；status 占比参考（D-05 下无 requested）：completed ≈ 82%、canceled ≈ 10%（其中 ~60% 超宽限期取消带取消费、~40% 宽限期免费取消，决策 D-06）、accepted/en_route ≈ 8%；start_time = INSERT（派单）时刻 |
| Payment | ≈ 51,300 | completed ≈ 49,200 行按 **~97%** 生成支付（≈47,700，**故意留 ~2-3% 未支付**使官方 Q2 反连接非空可截图）+ canceled 超宽限期取消行 ≈ 3,600（6,000 × 60%，D-06，amount = 取消费 ¥8） |

分布参数（对齐 A3 负载假设）：`start_time` 晚高峰（17–20 时）集中 ≈ 20%；`method` 占比：balance/cash/card ≈ 45/30/25%；`fare` 区间参照 TLC 车费分布（如 ¥10–¥120，均值 ≈ ¥35）；canceled 超宽限期取消行的 `fare` 固定 = 取消费 ¥8（D-06，口径参照 help.uber.com：取消费补偿司机接驾空驶，金额因城市而异，¥8 为课程简化值）。
