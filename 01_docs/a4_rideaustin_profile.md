## 三、联合验证：A/B 可按 RIDE_ID 行级 JOIN（修订 A4 旧结论）

- 两文件各 1,494,125 行，`RIDE_ID` 全量逐行比对**零错位**（同一 ID 轴、同序）；
- `A.created_date`（转 UTC）vs `B.dispatched_on`：**70.31% 精确到秒一致、99.98% 同分钟、100% 相差 ≤1 小时**（尾部差异来自夏令时切换周）；
- 结论：两文件是**同一批请求的行程侧 / 派单车辆侧两张侧写表**。旧结论"RIDE_ID 不同轴、不可行级 JOIN"**作废**——当时印象源于司机 ID 命名空间不同（A 脱敏 68.7 万 vs B 真实 4,976），属列语义差异而非可 JOIN 性差异。
- 对 D-10 的含义：行级拼回"行程+费率+车辆"可行，原始数据路线的一大障碍消除；**剩余障碍**：无支付方式列、乘客 26.1 万（官方设定 3,000）、无 canceled 行程状态（DECLINED 是派单口径）、坐标与里程脏值、`b''` 外壳清洗。

## 四、数据质量坑清单（使用前必读）

1. 文本列带 `b'...'` 外壳（导出痕迹），抽取参数时 strip；
2. `distance_traveled` 有 0 与 4.3 万公里级脏值，需截尾；
3. `requested_car_category` 混入 `b'HONDA'` 0.10%（品牌串档）；
4. 文件 A 坐标列与文件 B `dispatch_location_*` 均有异常/占位值；
5. 司机粒度只能用文件 B（A 的 `active_driver_id` 过度脱敏）；
6. 两文件 `rating`/`driver_rating` 语义不同（历史均分 vs 本单分）。
