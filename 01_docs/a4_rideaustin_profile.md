**① 标识与状态类**

| 属性 | 实测值域 |
|---|---|
| `RIDE_ID` | 与文件 A 逐行同轴（零错位） |

## 三、联合验证：A/B 可按 RIDE_ID 行级 JOIN（修订 A4 旧结论）

- 两文件各 1,494,125 行，`RIDE_ID` 全量逐行比对**零错位**（同一 ID 轴、同序）；
- `A.created_date`（转 UTC）vs `B.dispatched_on`：**70.31% 精确到秒一致、99.98% 同分钟、100% 相差 ≤1 小时**（尾部差异来自夏令时切换周）；
- 结论：两文件是**同一批请求的行程侧 / 派单车辆侧两张侧写表**。旧结论"RIDE_ID 不同轴、不可行级 JOIN"**作废**——当时印象源于司机 ID 命名空间不同（A 脱敏 68.7 万 vs B 真实 4,976），属列语义差异而非可 JOIN 性差异。
- 对 D-10 的含义：行级拼回"行程+费率+车辆"可行，原始数据路线的一大障碍消除；**剩余障碍**：无支付方式列、乘客 26.1 万（官方设定 3,000）、无 canceled 行程状态（DECLINED 是派单口径）、坐标与里程脏值、`b''` 外壳清洗。

## 四、数据质量坑清单（使用前必读）

1. 文本列带 `b'...'` 外壳（导出痕迹），抽取参数时 strip；
2. `distance_traveled` 有 0 与 4.3 万公里级脏值，需截尾；
3. `requested_car_category` 混入 `b'HONDA'` 0.10%（品牌串档）；
4. 文件 A 坐标列与文件 B `dispatch_location_*` 均有异常/占位值；
5. 司机粒度只能用文件 B（A 的 `active_driver_id` 过度脱敏）；
6. 两文件 `rating`/`driver_rating` 语义不同（历史均分 vs 本单分）；
7. **B 文件时间戳时区错位**（v1.1）：`dispatched_on` 为 UTC-naive；`driver_accepted_on` 带错误 −05:00 后缀，需 +5h/+6h 修正（见§二③）；
8. **total_fare 含 ≈$1.7 固定附加费、不含 tip/free_credit/round_up**（v1.1，组成见§二②）——对照表直接对均值列原值，勿按费率重算还原。

## 七、标定-留出验证拆分（10-23 组内收敛，C 方案收窄落地）

> 数据路线维持 D-10 定稿（**固定 seed 生成器 + RideAustin 标定**，不引入原始数据入库）；本节为报告"数据合理性有证据"的支撑方案，对应 rubric *sensible workload/dataset/baseline* 与 *realistic scenario*。

| 项 | 约定 |
|---|---|
| 拆分规则 | 按 `RIDE_ID` 哈希固定拆 **80% 训练段 / 20% 留出段**（确定性可复现；**不用时间拆**——只主张分布一致性，不主张预测，避免季节性解释负担） |
| 参数来源 | **C4 生成器参数只从训练段（80%，≈120 万行）重算**（数字与全量几乎不动，口径干净）；训练段数字与本档案全量实测并列注明 |
| 验证方式 | 生成 60,000 行后，与留出段出**分布对照表**（报告 §5 引用，数字按 D-08④ 同机产出） |

**可比维度（进对照表）**：车型四档占比 · 费率四档结构与 total_fare 均值 · 评分覆盖率与星级分布 · 晚高峰（17–20 时）占比。
**对照口径注（v1.1）**：① total_fare 均值直接用列原值（组成见§二②），勿按费率重算还原；② 晚高峰真实侧用 `created_date` 或修正后 `driver_accepted_on`（两者差秒级，注明用哪个）；③ 评分分布：真实侧 0.5 星步长、生成侧 1–5 整数（D-11），差异注一句。

**不可比维度（不进表，报告注明"业务规则为课程设定"）**：status 构成（真实数据全为完成单，无 canceled 语义）· Payment.method · 未支付率——真实数据无对应字段，放进表里反而暴露追问面。

**报告话术**：§1 "分布参数标定自 RideAustin 训练段（80%）并在留出段（20%）上验证一致性，业务洞察具潜在迁移价值"；§5 表下一句诚实边界——"验证的是分布一致性，非业务结论的外部效度"。

**责任分工**：C4 实现拆分与训练段参数（C，10-25 不变）· 对照表产出（D，同机纪律）· 登记入决策表（E，建议作 D-10 附注或 D-11）。
